# دیدار

دیدار برنامهٔ جلسه در مرورگر است و با PHP نوشته شده. افراد وارد اتاق می‌شوند، صحبت می‌کنند، دوربین را روشن می‌کنند، صفحه را به اشتراک می‌گذارند، روی تخته می‌نویسند، عکس و ویدیو و PDF را باز می‌کنند و چت می‌فرستند. گروه کوچک مستقیم از مرورگر به مرورگر وصل می‌شود. گروه بزرگ صدا و تصویر را از سرور مدیایی می‌فرستد که همین پروژه روی اوبونتوی خودتان نصب می‌کند. سرویس جلسهٔ بیرونی در کار نیست. حساب‌ها، اتاق‌ها، چت، ضبط‌ها و تنظیمات در پایگاه دادهٔ خودتان می‌ماند.

[English](README.md)

## چه چیزی نصب می‌شود

- ورود، زبان، تقویم و تعداد افراد آنلاین
- اتاق برای گروه کوچک، یا سرور مدیا برای گروه بزرگ
- میکروفون، دوربین، اشتراک صفحه، تخته و چت
- برگهٔ فایل برای عکس، ویدیو و PDF، با یادداشت زنده که ذخیره نمی‌شود
- ضبط جلسه که از کارت همان اتاق پخش می‌شود
- بکاپ کامل پایگاه داده از تنظیمات
- به‌روزرسانی از رلیز گیت‌هاب، بدون دست زدن به پایگاه داده و آپلودها

## چه چیزی لازم است

- اوبونتو با دسترسی root
- دامنه‌ای که رکورد A آن به IP عمومی همین سرور اشاره کند
- یک ایمیل برای گواهی HTTPS
- دسترسی خروجی HTTPS به Let's Encrypt (`acme-v02.api.letsencrypt.org`)
- این پورت‌ها روی IP عمومی باز باشند. در حالت `--net nat` آن‌ها را به آدرس خصوصی سرور فوروارد کنید:
  - SSH، روی پورتی که همین ماشین از قبل استفاده می‌کند (اگر عوضش نکرده باشید ۲۲)
  - ۸۰ و ۴۴۳ روی TCP
  - ۳۴۷۸ روی TCP و UDP
  - ۵۳۴۹ روی TCP
  - ۷۸۸۱ روی TCP
  - UDP از ۴۹۱۵۲ تا ۴۹۹۹۹ و از ۵۰۰۰۰ تا ۶۰۰۰۰

## حالت شبکه را انتخاب کنید

یکی را انتخاب کنید. نصب‌کننده خودش حدس نمی‌زند.

`--net nat` برای سرور خانه یا دفتر است. کارت شبکه آدرس خصوصی دارد، مثل `192.168.x.x`، و روتر پورت‌های بالا را به همان آدرس می‌فرستد. LiveKit همان IP عمومی را اعلام می‌کند. Coturn به شکل `external-ip=PUBLIC/PRIVATE` تنظیم می‌شود و `relay-ip` روی کارت خصوصی می‌ماند. IP عمومی همان رکورد A دامنه است. اگر رکورد هنوز آماده نیست، `--public-ip` را بدهید.

`--net direct` برای سروری است که خود کارت شبکه‌اش IP عمومی دارد. LiveKit و Coturn هر دو همان آدرس را استفاده می‌کنند. اگر کارت خصوصی باشد، این حالت متوقف می‌شود و می‌گوید `--net nat` را بزنید.

قبل از نصب، به‌روزرسانی و نصب مجدد، VPN را خاموش کنید (`vpn-stop`). اگر مسیر پیش‌فرض از تونل باشد، کار رد می‌شود تا آدرس مدیا آدرس VPN نشود. اگر Let's Encrypt در دسترس نباشد، نصب‌کننده فقط برای گرفتن گواهی `vpn-start` می‌زند و بعد `vpn-stop`. تا وقتی جلسه باز است VPN باید خاموش بماند. صدا و تصویر را از اینترنت موبایل تست کنید. گوشی روی همان وای‌فای سرور اغلب نام عمومی را باز نمی‌کند.

## نصب

این دستورها را روی اوبونتو با root بزنید. وقتی پرامپت نیست `--confirm-wipe` لازم است. این فلگ تمام پایگاه‌داده‌های MariaDB روی همین ماشین را پاک می‌کند. سایت‌های دیگر Nginx می‌مانند. فایروال فقط قانون جدید می‌گیرد و از نو ساخته نمی‌شود. رمز مدیر حداقل ۸ نویسه است. اگر `--admin-pass` را ننویسید، اسکریپت یک رمز می‌سازد و فقط یک بار در پایان چاپ می‌کند.

پشت NAT:

```bash
wget -qO didar.tar.gz "https://github.com/mrkioumarsi/didar/archive/refs/tags/v1.1.0.tar.gz?$(date +%s)"
tar -xzf didar.tar.gz
cd didar-1.1.0
sudo bash didar-install.sh --net nat --domain meet.example.com --email you@example.com --admin-user admin --admin-pass 'your-password' --confirm-wipe
```

اگر خود کارت شبکه IP عمومی است، همان دستورها را با `--net direct` به‌جای `--net nat` بزنید.

دامنه، ایمیل، نام کاربری و رمز را عوض کنید. اولین خط نصب باید `Didar 1.1.0 installer 20261113-net` باشد. اگر این خط نیست، دانلود قدیمی است. `didar.tar.gz` و پوشهٔ `didar-1.1.0` را پاک کنید و wget را دوباره بزنید.

فلگ‌های اختیاری: `--public-ip` فقط برای nat، `--admin-name`، و `--dir` وقتی برنامه کنار اسکریپت نیست. بدون `--confirm-wipe` اسکریپت صبر می‌کند تا `WIPE-DATABASES` را بنویسید.

نصب‌کننده Nginx، PHP، MariaDB، Coturn، LiveKit، گواهی HTTPS و پورت‌های رسانه را می‌گذارد و حساب مدیر را می‌سازد. اگر پوشهٔ دانلود برای کاربر وب خواندنی نباشد، برنامه از `/var/www/didar` سرو می‌شود.

در پایان، `SUCCESS` اول حالت مدیا را چاپ می‌کند، بعد میزبان و نام و کاربر و رمز پایگاه داده، بعد نام کاربری و رمز مدیر. قبل از بستن ترمینال آن‌ها را بردارید. کاربر پایگاه داده `didar` است، نامش `didar` است و میزبان `localhost` است. رمز root ماریا چاپ نمی‌شود. در `/root/.my.cnf` و `/etc/didar/secrets.env` است. رمز پایگاه دادهٔ برنامه هم در همان فایل است. رمز مدیر در `/etc/didar/admin.txt` هم هست. لاگ نصب `/var/log/didar-install.log` است. حالت انتخاب‌شده در `/etc/didar/media-mode` است و IP عمومی در `/etc/didar/pubip`.

`https://meet.example.com/` را باز کنید و وارد شوید. در تنظیمات گروه کوچک یا سرور مدیا را انتخاب کنید. آدرس‌ها از قبل پر شده است.

## به‌روزرسانی

وقتی گیت‌هاب رلیز جدیدتری دارد از این استفاده کنید. پایگاه داده، `config.local.php`، اتاق‌ها، ضبط‌ها و فایل‌های بارگذاری‌شده می‌مانند. فایل‌های برنامه عوض می‌شوند.

از تنظیمات گیت‌هاب را چک کنید و به‌روزرسانی را تأیید کنید. روی سرور، با VPN خاموش:

```bash
sudo didar-update
```

اگر این دستور نبود:

```bash
sudo bash /var/www/didar/didar-update.sh
```

## نصب مجدد همین نسخه

وقتی سرور از قبل روی ۱.۱.۰ است و می‌خواهید فایل‌های همین رلیز را دوباره بگیرید، از این استفاده کنید. همان تگ را یک بار دیگر دانلود می‌کند. پایگاه داده، `config.local.php` و آپلودها می‌مانند. اول VPN را خاموش کنید. از تنظیمات «نصب مجدد نسخه فعلی» یا:

```bash
sudo didar-reinstall
```

```bash
sudo bash /var/www/didar/didar-reinstall.sh
```

نصب اول اگر ناتمام مانده باشد با نصب مجدد درست نمی‌شود. رلیز را دوباره دانلود کنید و `didar-install.sh` را اجرا کنید. این کار MariaDB را پاک می‌کند.

## گواهی

نصب‌کننده در مرحلهٔ آخر از Let's Encrypt گواهی می‌گیرد. اگر این سرویس روی IPv4 در دسترس نباشد و `vpn-start` وجود داشته باشد، VPN را فقط برای همان مرحله روشن می‌کند و بعد خاموش می‌کند. اگر باز هم نشد، `vpn-start` را بزنید، نصب را دوباره اجرا کنید، بعد `vpn-stop`.

بعداً در تنظیمات می‌شود گواهی خودکار ماند یا کلید خصوصی، کلید عمومی، گواهی و باندل را چسباند. ذخیره، وب‌سرور را یک بار ری‌استارت می‌کند. اگر به حالت خودکار برگردید و آن گواهی نباشد، گواهی دستی سر جایش می‌ماند. تمدید، گواهی خودکار را به Coturn هم کپی می‌کند. `didar-renew` و `didar-ssl` برای همین کار نصب می‌شوند.

## حذف

دو حالت. بدون `--yes` اسکریپت تا وقتی کلمهٔ تأیید را ننویسید چیزی پاک نمی‌کند.

`--soft` — بنویسید `REMOVE`. پایگاه داده و کاربر دیدار، فایل‌ها، سایت Nginx دیدار، استخر PHP دیدار، LiveKit، Coturn و گواهی دیدار پاک می‌شوند. Nginx، PHP، MariaDB، بقیهٔ پایگاه‌داده‌ها، بقیهٔ سایت‌ها، certbot، ffmpeg، SSH و UFW می‌مانند.

```bash
sudo didar-uninstall --soft
```

`--hard` — بنویسید `DELETE`. به‌علاوه Nginx، PHP، MariaDB با تمام پایگاه‌داده‌ها، certbot، ffmpeg، همهٔ گواهی‌های همین سرور و قوانین فایروالی که نصب‌کننده باز کرده هم برداشته می‌شوند. SSH و خود UFW می‌مانند. برگشت ندارد.

```bash
sudo didar-uninstall --hard
```

بدون پرامپت، `--yes` را کنار `--soft` یا `--hard` بگذارید. اگر دستور نبود:

```bash
sudo bash /var/www/didar/didar-uninstall.sh --soft
sudo bash /var/www/didar/didar-uninstall.sh --hard
```

## اگر صدا یا تصویر نیاید

LiveKit به یک آدرس واقعی سنجاق شده و `use_external_ip` خاموش است. آدرس را از STUN پیدا نمی‌کند و آدرس VPN را برنمی‌دارد. در حالت nat، Coturn آدرس عمومی را اعلام می‌کند و رله از کارت خصوصی است. در حالت direct هر دو طرف Coturn همان کارت عمومی است.

مرورگر از آدرس‌های STUN و TURN داخل تنظیمات استفاده می‌کند (پورت ۳۴۷۸، و ۵۳۴۹ برای TLS). گزینهٔ «فقط از طریق TURN» خاموش است مگر خودتان در تنظیمات روشن کنید. فقط وقتی روشن کنید که ارتباط مستقیم ناپایدار است و TURN از قبل پر شده.

فوروارد پورت‌های بالا، درست بودن `/etc/didar/pubip`، و اجرای `vpn-stop` را چک کنید. بعد از اینترنت موبایل تست کنید.

## داخل برنامه

- زبان را موقع ورود انتخاب کنید و بعداً از پروفایل عوض کنید. زبان تازه یک فایل در `lang/` است.
- تاریخ‌ها با تقویم و منطقهٔ زمانی تنظیمات نشان داده می‌شوند.
- قدرت رمز در تنظیمات است: کم، متوسط، زیاد.
- تعداد آنلاین از خود برنامه است. پردازنده، حافظه و پهنای باند وقتی دیده می‌شود که سرور اجازهٔ خواندن آن‌ها را بدهد.
- مدیر اتاق می‌تواند جلسه را ضبط کند. فایل روی همان اتاق می‌ماند و از کارت اتاق پخش می‌شود.
- برگهٔ فایل‌ها عکس، ویدیو و PDF را نشان می‌دهد. یادداشت روی عکس و PDF فقط برای حاضران همان جلسه است و ذخیره نمی‌شود. افراد داخل اتاق می‌توانند فایل را دانلود کنند. مدیر اتاق حذف می‌کند و می‌تواند به دیگران اجازهٔ بارگذاری بدهد.
- وقتی مدیر صحنه، تخته یا فایل‌ها را باز می‌کند، اتاق همراه می‌شود. فایلی که مدیر باز کند به اتاق نشان داده می‌شود.
- از تنظیمات می‌شود بکاپ کامل پایگاه داده را گرفت.
